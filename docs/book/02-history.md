# 从心理测量到动态 Agent Eval

> **本章问题**：今天关于污染、饱和、Judge 和排行榜的争论，历史上从哪里来？

AI benchmark 看似是计算机科学的新制度，实际继承了心理测量、统计推断、实验科学、软件测试和竞赛文化的多重传统。理解这段历史的价值，不是记住首发年份，而是看清每一次制度创新解决了什么问题，又创造了什么新盲区。

::: tip 综合判断 · 历史叙事口径
下面七阶段是本书为了连接测量问题而做的历史综合，不是学界公认的唯一分期。项目年份与原始主张由章末一手来源支持；“解决了什么、留下什么设计债”是作者的解释框架。
:::

## 第一阶段：不可见能力如何被测量

人的智力、知识或人格无法直接观察，测量者只能从有限行为样本推断潜在属性。心理测量由此形成几组至今仍有效的区分：信度不等于效度；题目数量不等于内容覆盖；一个分数只有在明确用途、群体和条件下才有解释；测量误差不是数据清洗后便会消失的噪声。

项目反应理论（IRT）进一步把题目难度、区分度和猜测纳入模型。它提醒我们：一个 benchmark 的题并非等价硬币，系统在不同能力区间需要不同信息量。今天使用 IRT 校准语言模型题集时，仍需检查单维性、局部独立和差异项目功能；否则漂亮的能力刻度只是更复杂的错测。

## 第二阶段：图灵把本体问题转成行为协议

1950 年，图灵没有直接回答“机器是否真的思考”，而是用模仿游戏把问题变成可观察的人机对话。它建立了 AI 评测的基本操作：当内部机制难以直接测量时，设计一个行为协议产生可比较证据。

同一设计也预示了边界。协议允许观察什么，就定义了能力被看见的部分；行为相似不等于机制相同；测试者和受试者会适应规则。今天的静态问答、Arena 偏好与 Agent 沙箱都继承了这个结构。

## 第三阶段：数据集与 shared task 建立可比性

UCI 数据集、TREC 信息检索评测和 CoNLL shared task 让研究共同体接受同一数据、切分、指标和截止期。可重复比较取代了各自挑选演示，累积进步成为可能。软件基础设施、隐藏测试和共同任务社区由此成为 benchmark 的一部分。

代价也随之出现：数据集容易被视为任务本身；一个指标会压缩多种质量；研究资源向容易排名的问题集中。系统逐渐从理解目标问题转向适应测量仪器。

## 第四阶段：ImageNet 与排行榜文化

ImageNet 把大规模标注数据、年度竞赛和单一主指标结合，显著推动视觉模型。GLUE、SuperGLUE 随后用多任务 suite 推动语言理解。清晰数字能汇聚人才和计算资源，但当指标成为资源分配依据，Goodhart 压力同步增强。

排行榜文化产生了一个微妙变化：benchmark 从科学仪器变成产品发布叙事。系统配置、提示、工具和提交次数有时隐藏在一个模型名之后；小数点差异得到传播，任务审计和不确定性却留在附录。

## 第五阶段：大模型的多任务、多指标与动态化

MMLU、BIG-bench、HELM 等把知识、推理、场景和多指标带进统一框架。随着公开题进入训练语料、选择题饱和，社区转向专家原创、难检索、隐藏和滚动题集。动态 benchmark 能降低直接污染并持续发现新失败，却牺牲跨版本可比性和外部审计。

中国的 C-Eval、CMMLU、OpenCompass 等补足中文考试、知识与模型接入，但也说明多语言评测不是翻译工程。语言、文化、制度、软件生态和业务惯例都会改变任务需求。

## 第六阶段：Agent 把“答案”改成“行动”

WebArena、OSWorld、SWE-bench、τ-bench、TheAgentCompany 等把模型放入有状态环境。评测对象开始浏览、调用工具、修改文件与数据库、处理失败并决定何时停止。最终文本不再是真值：Agent 可以说“完成”而环境没有变化，也可以产生正确状态却使用危险路径。

因此现代 Agent eval 引入环境重置、执行式 grader、轨迹、工具预算、基础设施错误分类和连续可靠性。Harness 从实验脚手架变成被测系统的一部分。

## 第七阶段：从静态题库走向持续资格

当 AI 进入真实工作，benchmark 需要连接发布门禁与生产复证。新的测量系统同时保留稳定锚题、隐藏资格题、滚动前沿题和生产回归。题集退役不再意味着失败，而是承认仪器已经饱和、污染或不再代表部署。

历史沿革可以压缩成一条主线：

```text
行为可观察
→ 条件可比较
→ 多任务可概括
→ 环境状态可验证
→ 组件贡献可归因
→ 岗位责任可授权
```

每次向右移动，生态效度提高，控制、复现和公开性却变难。没有任何时代的新方法淘汰旧方法：静态题仍适合廉价诊断，交互环境适合行动验证，生产证据适合授权。成熟体系知道何时使用哪一层。

## 六次历史迁移留下的设计债

历史不是一条只向前的进步线。每次解决旧问题，也把新问题带入基础设施。

| 迁移 | 解决的问题 | 新的设计债 |
|---|---|---|
| 心理测量尺度 | 从有限行为推断不可见能力 | 单维模型可能压扁多维能力 |
| 图灵式行为协议 | 把哲学问题变成可观察比较 | 测试边界决定“什么能被看见” |
| Shared task | 统一数据、切分和指标 | 数据集被误当成完整任务 |
| Leaderboard | 让进步清晰可传播 | 优化目标替代真实目标 |
| 多任务/多指标 | 扩展覆盖与责任维度 | 聚合权重继续隐藏价值判断 |
| Agent 环境 | 验证行动与终态 | 环境、Harness 和预算难以控制 |

设计新 benchmark 时，不必假装自己站在历史之外。相反，应主动说明借用了哪种制度，并继承了什么风险。使用排行榜就要管理提交过拟合；使用动态题集就要处理跨版本等值；使用仿真就要说明现实差距；使用专家题就要披露样本和评审条件。

## 一个历史项目的四种读法

以 ImageNet 为例。工程读法关注数据规模、年度竞赛和模型进步；测量读法会问标签和类别是否代表视觉理解；制度读法关注单一指标如何集中研究资源；治理读法关注数据、许可、偏差与项目饱和后如何退出中心舞台。同一个 benchmark 同时是数据集、测量仪器、竞赛制度和社会协调机制。

今天阅读 SWE-bench、GDPval 或 SkillsBench 也应采用四种读法。只看技术题目会漏掉提交规则和 Harness；只看社会争议会漏掉执行式 verifier 的真实进步。系统认知来自同时保留这几层。

## 历史如何帮助预测新争议

当一个新榜单快速成为采购或资本叙事，可以预期针对性优化、选择性提交和小数点传播；当一个新动态集宣称解决污染，可以预期可复现与跨期比较的反作用；当一个 Agent 环境宣称更真实，可以预期环境维护、工具公平和人类基线争议。历史不能告诉我们具体哪条题错，却能提前列出应审计的失败模式。

## 双案例镜头

云舟零售可以用公开中文知识集筛掉明显不合格的模型，但订单履约仍需要有状态沙箱。星桥硬件可以用代码和多模态题诊断基础能力，但研发放行必须检查真实工件间的追踪关系。历史告诉两家公司：不要要求底层诊断题承担岗位资格的责任。

## 练习：画出你的评测谱系

选一个现有 benchmark，标注它继承了哪种传统：考试、shared task、软件测试、偏好比较、仿真或生产监控。然后写出它为了获得可比性牺牲了什么，以及增加哪一层证据才能支持你的目标决策。
