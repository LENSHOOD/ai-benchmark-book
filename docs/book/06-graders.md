# Grader、人类评审与 LLM Judge

> **本章问题**：谁来判断答案对不对，以及如何知道裁判没有系统性地判错？

Grader 是把系统行为转成评测结果的机制。它可能是精确答案匹配、单元测试、数据库断言、领域算法、规则、人工 rubric 或 LLM judge。Grader 不是 benchmark 的附属脚本，而是测量模型的一部分：它决定什么行为被看见，什么错误被忽略。

Strict、diagnostic 与 veto 如何连接前后章节，见[框架总览](/appendix/framework-map)。

## 从可验证性最高的证据开始

推荐的优先级是：

1. 环境终态和不可变业务断言；
2. 领域算法、编译、仿真与单元测试；
3. 必要轨迹、权限和政策规则；
4. 行为锚定的专家 rubric；
5. 经人工校准的 LLM judge。

这不是说排在前面的永远更重要，而是越靠前越容易复核。开放写作质量确实需要人或模型判断，但“退款是否发生两次”“安全测试是否缺失”“代码是否通过回归”不应交给语言模型凭印象决定。

## Strict success、诊断分与 Veto

业务评测最好同时输出三类结果。

**Strict success** 要求全部关键终态正确、禁止状态未发生、必要升级完成。它用于资格门禁。

**诊断分** 将目标拆成子项，展示系统做对了多少以及失败位置。它用于研发，不应把部分完成包装成业务价值。

**Veto** 代表不可被平均质量抵消的严重行为，例如越权付款、泄露、未经批准的安全放行或绕过联锁。一旦触发，任务失败并进入独立风险报告。

过程分适合检查必须步骤、禁止工具、证据链、冗余调用、恢复和升级，但不要强制复制唯一示范轨迹。强系统可能找到更短、更安全的新路径；此时应触发人工审查和任务规范更新，而不是自动判错。

## 人工评审不是无误差金标准

专家也会受到信息、时间、顺序和组织激励影响。人工评估需定义评审者资格、培训、可查工具、时限、盲化、重复标注和分歧仲裁。人类基线还要说明是普通用户、领域专家还是在真实工具和时间条件下工作的熟练员工。

至少抽取重叠样本估计一致性。比一个总体一致率更有价值的是分歧切片：专家是否在政策冲突、开放建议或临界门禁上分歧。若人类自己无法稳定判断，系统分数不应伪精确。

## LLM-as-a-Judge 的位置

LLM judge 擅长扩展开放任务评估、解释 rubric 和生成诊断，但会出现位置、冗长、风格、同源自偏好和推理能力限制。候选输出还可能对 judge 进行提示注入。因此候选内容、裁判指令和参考材料要分层隔离。

最低校准流程包括：建立专家 gold；盲化候选身份和顺序；交换 A/B 位置；比较多个 judge 或模型族；计算分类指标和分维度混淆；对低置信、严重分歧和 veto 案例人工仲裁；固定 judge 版本和 Prompt。模型或 Prompt 更新后重新校准。

Judge 的评测不能只看与人类平均相关。若它在发布阈值附近频繁翻转、把危险输出判为通过，即使整体相关很高也不可用。阈值附近的条件错误率比总体相关更接近决策风险。

## Grader 也要接受单元测试

每项断言至少用四类候选测试：合理正解、替代正解、近错解和危险捷径。若替代正解被拒绝，grader 过窄；近错解被接受，grader 过宽；危险捷径被接受，安全门禁失效。

Grader Card 应记录：目标构念、输入、规则、权重、veto、依赖、版本、已知偏差、人工校准、覆盖测试和申诉流程。任何修改都可能改变历史分数，必须版本化。

## 一个 Judge 校准工作坊

假设团队需要评价 300 份开放式根因分析。先由两位硬件专家独立标注 60 份，维度包括证据适用、因果论证、替代解释和验证计划；分歧经第三人仲裁。将 40 份用于设计 Judge Prompt，20 份保持盲测。候选身份与顺序随机，Judge 不看到最终门禁标签，只得到工件和 rubric。

第一轮不要只算平均相关。建立每个维度的混淆矩阵，特别检查“证据缺失但文风专业”的近错和“结论保守但证据充分”的替代正解。交换顺序复测，比较同源与异源 Judge。若严重错误集中在“建议放行”，将该维度移回确定性规则或专家，而不是继续微调一个总分 Prompt。

校准产物包括 gold 样本、Prompt、模型快照、温度、输出 schema、阈值、分歧规则和已知失败。Judge 更新后，在固定 gold 上做回归，不能默认新模型更会评。

## Grader 的三种漂移

**代码漂移**来自规则和测试修改；**数据漂移**来自环境或政策变化；**语义漂移**来自团队对“好”的定义改变。三者都可能重写历史结果。变更记录应说明哪些旧运行可重评分，哪些必须重跑。

例如退款政策额度改变，旧 trace 可以用新规则重评分，但如果候选当时没有看到新政策，重评分不能代表新部署能力；需要在新环境重跑。区分重评分和重执行，避免时间穿越。

## 申诉是发现新合理路径的传感器

当候选找到 grader 未覆盖但业务合理的路径，申诉不应被视为麻烦。评审者判断它是替代正解、任务歧义还是危险投机。替代正解进入 grader 测试并回溯重评分；任务歧义触发修订；危险投机加入负断言。一个允许申诉且公开修订影响的 benchmark，通常比拒绝一切例外的仪器更可信。

## 不确定输出怎样进门禁

Grader 可以输出 `pass`、`fail`、`veto`、`needs_review`，而不是强迫所有 case 二分。`needs_review` 的比例、严重度和人工分钟必须报告；系统不能通过大量转人工伪装质量。资格规则预先说明 review 如何进入分母、由谁仲裁及何时视为证据不足。

## 双案例镜头

云舟零售首先读取订单、库存和资金终态；模型 judge 只评价客户解释是否清晰且不误导。星桥硬件首先检查需求追踪、测试证据、器件约束和审批；专家 rubric 评价根因论证与验证计划，LLM judge 只在低风险诊断维度辅助。

## 练习：攻击你的 Grader

为一个任务写出五个候选：完全正确、表面漂亮但未执行、结果正确但路径不同、部分完成、危险捷径。运行或人工检查 grader 是否给出预期结果。每发现一个错误，先修 grader 测试，再修改规则。
