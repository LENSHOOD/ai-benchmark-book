# 从任务宇宙到可维护题集

> **本章问题**：怎样把现实世界中无限、动态的任务，变成有限但有代表性的 benchmark？

任务宇宙（task universe）是目标部署中所有相关情形的概念总体。题集只是从这个总体抽取的有限样本。很多团队从“手头有哪些数据”开始，于是可得数据反过来定义能力；正确顺序是从部署、决策和风险推导需要观察的任务，再决定如何取得样本。

本章的任务宇宙、频率集与风险集在全书证据链中的位置见[框架总览](/appendix/framework-map)。

## 建立任务分类，而不是堆案例

任务宇宙至少需要五个轴：

- 业务频率：日常高频、低频边界、罕见事故；
- 难度来源：知识、推理、工具、长程依赖、模态和协作；
- 状态条件：完整、缺失、矛盾、过期、并发和系统故障；
- 风险：可逆、需审批、不可逆、安全或合规关键；
- 人机关系：自主完成、建议人批准、必须升级和禁止处理。

分类的目的不是形成漂亮表格，而是发现空白。若一个格子对部署重要却没有任务，构念证据不完整；若一批任务无法映射到任何构念，它们可能引入无关方差。

## 频率集与风险集必须分开

生产频率适合估计日常价值，但罕见严重事件会被均值淹没。企业 benchmark 因而应至少维护两套分布：频率集按真实发生率抽样，回答吞吐、质量和成本；风险集按严重性、不可逆性和攻击面抽样，回答是否允许上线和授权。

两套分数不能简单平均。数百个普通订单成功，不能抵消一次未经审批的高额退款；大量普通测试报告正确，也不能抵消一次安全证据缺失时的错误放行。

## 四条任务来源

第一条是领域专家根据真实工作产品原创。它能覆盖尚未进入日志的新要求，但可能反映理想流程而非实际工作。

第二条是从生产事件、人工大改和事故中抽取。它生态效度高，却需要脱敏、去重和重新定义可执行真值。

第三条是从政策、FMEA、红队与威胁模型构造边界条件。它适合发现危险捷径，但不能估计自然频率。

第四条是参数化合成。它能扩大组合覆盖、控制因果因素，却容易生成不现实任务。合成器也要经过领域专家和分布检查。

健康题集混合四条来源，并保存来源标签，避免把对抗题权重误解成生产概率。

## 写出可独立判定的 Task Spec

一条任务至少包括：稳定 ID、构念映射、初始状态、可见输入、允许工具、目标终态、禁止终态、升级条件、预算、grader、严重度、来源、版本与切分。对于开放任务，还应给行为锚定 rubric 和可接受的多种路径，而非唯一参考答案。

正断言与负断言必须同时存在。创建采购单的任务不仅检查采购单存在，还要检查供应商、金额、审批正确，并确认没有重复单、错误库存修改和越权通知。

## 切分的真正单位

随机行切分经常制造虚假泛化。同一客户、订单、产品、设备、文档模板或代码仓库的近重复可能跨越训练与测试。企业数据应按实体、时间、组织或生成模板分组；时间敏感政策要保留未来切分；多个版本的同一事故要绑定在同一集合。

污染也不是“题目全文是否出现”的二元判断。答案、解析、模板、衍生合成数据、评测 Skill 和开发者针对公开榜单的反复优化都会改变独立性。控制方法包括原创私有题、时间切分、近重复检测、限制隐藏集提交、记录接触次数、滚动换题与锚题等值。

## 动态题集如何保持可比

固定题集便于纵向比较，却会饱和和污染；动态题集保持新鲜，却让不同时间分数不可直接比较。折中方案是保留一组受保护锚题，同时滚动加入新题，通过重叠系统或尺度模型连接版本。发布时必须同时报告 suite 版本和变更记录。

坏题审计是常规治理。不可解、歧义、多个合理答案、grader 错误、环境初始化失败和答案泄漏都需要修订。修订后应回溯重评分历史系统，并明确榜单变化来自模型还是仪器。

## 从原始事件到资格任务的流水线

一条生产事件不能原样塞进题集。第一步保存事实：输入、时间、版本、动作、终态和人工修复。第二步脱敏并移除与构念无关的偶然细节。第三步重建最小环境，确认领域专家能独立完成。第四步写正/负断言和严重度。第五步构造近邻变化，检查任务是否只靠记忆。第六步让 grader 通过合理正解、替代正解、近错和危险捷径。第七步决定进入开发、资格、风险还是事故集。

这个流程保留了事件的失败机制，又避免把客户标识、偶然文案和未来答案泄漏给候选。原始事件与合成任务之间要保存可审计映射，但访问权限可以不同。

## 参数化合成如何不生成“玩具题”

合成器应从真实约束图出发，而不是随机拼接名词。参数之间存在依赖：受监管商品限制拆单；器件封装决定 PCB 兼容；客户等级影响 SLA 但不能绕过隐私。先定义合法状态生成器，再对少数因素做干预；为每个组合运行领域不变量；抽样专家盲审现实性；比较合成与生产在关键特征上的分布。

合成任务最适合覆盖稀有组合、构造可控反事实和压力测试。它不应用来估计真实频率，也不能替代生产证据。

## 题目难度不是一个数字

Agent 任务的难度可能来自长程步骤、隐藏依赖、工具可靠性、信息缺失、政策冲突、模态或风险限制。两个同样低通过率的任务，修复路径完全不同。目录应记录需求向量，而不是只给 `hard` 标签。

试测后分析地板、天花板、任务级方差和失败类别。若所有系统都因环境错误失败，应修环境；若只有专家能解但彼此分歧，应修规范；若强系统通过但弱系统随机，才可能是有用区分题。

## 资格集访问是一种权限

记录谁在什么时间以何种目的接触隐藏任务、获得何种反馈。研发只收到聚合失败类型，还是看到逐题 trace，会改变过拟合风险。反复失败后现场修改并继续提交，本质上已将资格集转成开发集。预先规定提交次数和换题策略，比事后声称“我们没有训练”更可信。

## 双案例镜头

云舟零售的分类轴包含订单价值、客户等级、库存位置、承运事件、政策版本与是否需审批。星桥硬件包含研发阶段、需求安全等级、器件生命周期、测试证据状态、缺陷严重度和工程变更权限。两家公司都按实体和时间切分：同一订单族或同一缺陷/设计版本不能跨集合。

## 练习：构造 5×5 任务地图

选择两个最重要的分类轴，各分五档，形成 25 个格子。标出生产频率、严重度、现有样本数和 grader 可行性。不要立刻补齐所有格子；先解释哪些空白是合理边界，哪些是危险盲区。
