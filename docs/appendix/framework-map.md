# 框架总览

全书有不少编号框架，但它们不是十套互相竞争的方法。把它们放在一起看，其实只是一条工作链：你要做什么决定，想测什么，怎样选题和观察，怎样解释结果，最后何时给权限、何时重新验证。

```text
决策用途
  ↓
构念与效度 ──→ 任务宇宙与切分 ──→ Episode / 环境 / 协议
  ↓                    ↓                       ↓
系统边界          正常＋风险＋近错          状态＋轨迹＋故障
  └────────────────────┬──────────────────────┘
                       ↓
              Grader：strict / diagnostic / veto
                       ↓
              统计：逐题 / 配对 / 区间 / 切片
                       ↓
         决策：研发修复 / 选型 / 资格 / 授权 / 复证
```

## 十个局部框架放在哪里

| 书中框架 | 主要章节 | 在主线中的角色 | 典型产物 |
|---|---:|---|---|
| 八层测量系统 | 3 | 把一套 benchmark 说完整 | Charter、协议卡 |
| 五类效度证据 | 4 | 防止分数被过度解释 | 效度论证、反证登记 |
| 任务宇宙轴与双分布 | 5 | 从部署空间抽样 | 频率集、风险集、切分表 |
| strict / diagnostic / veto | 6 | 把状态转成决策证据 | Grader Card、攻击测试 |
| 工具调用四层 | 8 | 定位 Agent 失败层级 | 状态断言、轨迹标签 |
| Model×Harness×Skill | 9–11 | 分离系统组件与交互 | Harness Card、消融矩阵 |
| Skill 七段链与三条件 | 10 | 定位发现、执行和冲突 | oracle/retrieval/open 实验 |
| 企业四层证据 | 12 | 连接公开评测与生产 | 公共、合成、私有、生产证据 |
| 分级上岗与能力执照 | 15 | 将资格结果约束到权限 | Release Gate、能力执照 |
| 十二维 benchmark 审计 | 16 | 评测评测本身 | 审计报告、退役决策 |

## 三种容易误合并的层级

书里有三种“证据层”，很容易混在一起。第 3 章的诊断/资格/生产说的是**拿分数做什么决定**；第 12 章的公共/合成/私有/生产说的是**离真实部署有多近、哪些内容能公开**；第 6 章的状态、规则、judge、专家说的是**评分依据从哪里来**。它们可以组合，但不能互相代替。

例如，企业私有资格考试可以同时用状态验证器、领域规则和专家；公开诊断 benchmark 也可以有可执行环境。先问“这个分数要支持什么决定”，再问“题目来自哪里”“依据什么评分”，就不会把几套框架硬塞成一个金字塔。
