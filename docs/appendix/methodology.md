# 方法、证据与边界

本书建立在截至 2026-08-22 的系统研究上，并在 2026-08-28 对高风险引文、arXiv 元数据和发布实现做了复核。随书账本现注册 140 个来源 URL、136 条可定位研究证据和 70 个代表 benchmark，覆盖历史与基础模型、Agent/Harness/Skill、企业/FDE 与四行业实践。51 条 arXiv 记录已通过一手 API 批量核验，连同两条其他一手记录，当前共 53 条标记为 `verified_primary`，其余 87 条保持 `unverified`。注册表示“进入核验队列”，不自动等于作者、题名、版本和论断支持关系均已审定；读者应结合每条记录的 `metadata_status` 使用。新增 URL 中包含同一项目的论文页与官网，因此“140”不是 140 个彼此独立的证据实体。

正文没有把研究报告拆章，而是按教学链路重写：用途 → 构念 → 任务宇宙 → grader → 系统组件 → 实验 → 企业授权。主要事实优先回到论文、官方项目、代码、标准和研究机构材料；厂商内容只用于证明其自身方法或主张。来源清单见[参考文献](./references)。

## 合成案例边界

云舟零售和星桥硬件均为虚构企业。任务、政策、订单、器件、测试和缺陷是教学合成资产。两套参考实现使用可复现的规则策略替身与受控故障注入，用于验证答案隔离、环境状态、grader、因子矩阵、幂等恢复和任务级配对接口；运行数字不构成真实模型、行业或物理产品能力证据。

企业使用时必须以自己的流程、基线、风险、权限和领域专家判断重新确定任务与阈值。硬件真实实验还需设备校准、物理安全、数据完整性和法定责任，不能由合成沙箱替代。

## 已知限制

- Agent、Harness 和 Skill benchmark 更新极快，具体项目状态可能变化；
- 闭源训练数据使污染无法被完全证明；
- 公开企业案例稀缺，长期 ROI 的独立因果研究不足；
- 部分二手转述来源无法稳定访问，相关论断只在能回到论文、官网或代码等一手材料时进入事实叙述；
- 统计示例为教学简化，真实共同故障可能破坏独立假设；
- 本版未连接真实模型 API、PLM、OMS/WMS 或实验设备。

## 维护机制

稳定方法留在正文；新项目、修订、污染和退役进入 Benchmark Radar。重要事实修订需提供原始来源；代码修改需通过两套示例测试、内容链接检查和 VitePress production build。
