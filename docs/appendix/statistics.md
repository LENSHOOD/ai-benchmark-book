# 统计速查

这不是统计教材，而是一张防错清单。它帮你回答三件事：该怎么算，数字有多不确定，结果能不能支持发布决定。

## 先明确观测层级

一次运行（trial）属于某个“系统—任务”组合，任务又可能属于某个客户、设备或领域。同一道题重复跑十次，不等于有十道独立题。先画清这些层级，再决定怎样算区间。

## 二元成功率

若 $y_i \in \{0,1\}$，成功率为：

$$
\hat p = \frac{1}{n}\sum_{i=1}^{n}y_i
$$

不要只写“成功率 80%”。同时写明成功次数、总次数和不确定区间。对独立、具有共同成功概率的二元观察，可以用 Wilson 区间或精确二项区间，避免小样本下直接套正态近似。同一任务的多次 trial 往往相关，不能把它们全部塞进独立二项公式；要按任务、客户或故障批次等实际结构处理。

普通百分位 bootstrap 也有边界。假设十道独立二元任务全部成功，从这十个 1 中怎样重采样都还是 1，区间就退化成 `[1, 1]`。同一数据的双侧 95% Wilson 区间约为 `[0.7225, 1]`。全败时也有类似问题：零宽度的重采样区间，不代表没有不确定性或风险。

## 配对差值

让候选 A 和 B 跑同一批任务，再计算 $d_i = y_{i,B}-y_{i,A}$。报告平均差值、胜/负/平题数和区间。这样做叫配对比较，可以减少题目难度不同带来的干扰。

## 两层 Bootstrap

先明确目标。若把任务内多次运行汇总成一个均值，再重采样配对的任务差值，重点是在这组题之外重新抽题的不确定性。本书比较函数采用这种任务级方法。固定这批题、只研究再次运行的波动，是另一个估计目标。

任务和 trial 两层重采样可以作为候选方法，但必须符合数据的抽样结构：

1. 从任务中有放回地抽样，也就是同一道题可以被抽中多次；
2. 对每道抽中的任务，再从它的多次运行中有放回地抽样；
3. 计算目标统计量；
4. 重复很多次，用结果分布的分位数形成区间。

比较 A/B 时，同一题应一起抽中；若 trial 共享故障或随机条件，也要保留对应关系。如果多次失败可能来自同一次故障，就按事故批次、客户或时间段抽样。两层方法并不自动保证覆盖正确，小样本和全成、全败仍需检查。

## pass@k 与 pass^k

在独立且单次成功率为 $p$ 的简化条件下：

$$
pass@k = 1-(1-p)^k
$$

$$
pass^k = p^k
$$

`pass@k` 问的是“同一道题试 k 次，至少成功一次的机会有多大”，适合搜索候选答案。`pass^k` 问的是“重复做同一道题 k 次，能否每次都成功”，更关注稳定性。不同题的成功概率不同时，应先逐题计算，再汇总，不能把总平均成功率直接代入幂函数。

连续处理 k 个不同业务任务，是另一个问题。只有各次独立且成功概率相同时，才能直接使用上面的 $p^k$。真实服务可能共享故障或政策错误，所以还要观察连续失败和共同故障，不能只套公式。

## 混合效应思路

数据足够多时，可以用下面的混合效应 logistic 模型，同时估计组件影响和任务差异：

```text
logit(P(success)) ~ model + harness + skill
                  + model:harness + model:skill + harness:skill
                  + model:harness:skill
                  + (1 | task) + (1 | domain)
```

最后的三阶项表示：Skill 的效果可能同时取决于模型和 Harness。若只保留两两交互，就假设三阶作用可以忽略，需要用各组合实测结果检查。跑了全交叉实验，不等于这个简化假设已经成立。

数据少时，不要用复杂模型制造“很科学”的错觉。两个模型、两个 Harness、两种 Skill 条件的八格结果，以及逐题配对差值和区间，通常更容易解释。任务嵌套在领域中时，还要让模型中的任务身份和分组方式与实际数据对应。

## 看结果再停，区间也要跟着改

普通固定样本区间，并不自动适用于“每跑一批就看，领先了就停”。即使提前登记停止规则，选择依赖结果时仍可能产生偏差。任务加权只处理目标任务分布，不能修正所有早停影响。

入门实践可以先在开发集探索，再用新任务按固定方案确认。确需连续观察时，应选择与数据假设相符的顺序方法。[置信序列](https://arxiv.org/abs/1810.08240) 是一类允许连续查看的区间，但仍有适用条件，不能仅给普通区间换一个名字。具体反例见[第 11 章](/book/11-experiments)。

## 最小实际重要差异

看结果前，先写下“提升多少才值得发布”。一个百分点对每天百万次的流程可能很重要，对只有 20 道题的小集合却可能只是测量波动。最好把差异换算成成功单量、人工时间、成本或事故风险。

## 多重比较

比较的模型、切片和指标越多，越容易偶然找到一个“显著提升”。因此要提前指定主要比较，完整报告失败结果，并把事后发现标成探索性结果。比较很多时，还要控制错误发现率。不要只展示赢的切片。

## 推荐最小报告

- 系统、题集（suite）、评分器和预算的版本；
- 任务数、运行次数、缺失数据和环境错误；
- 严格成功、veto、主要诊断指标；
- 按任务计算的配对差值和区间；
- 频率集/风险集与关键切片；
- 成本、尾延迟、人工接管；
- 预注册偏离、已知限制和原始逐题结果。
