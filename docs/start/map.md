# 全书地图

全书一直在回答同一件事：我们凭什么相信一个 AI 系统可以承担某项工作？

```text
想支持的决策
  ↓
目标构念 → 任务宇宙 → 有限题集 → 评测协议
  ↓
Model × Harness × Skill × Environment × Budget
  ↓
Grader → 逐题证据 → 统计解释 → 发布与授权
  ↓
生产事故 / 研发缺陷 → 新回归 → 复证与治理
```

## 五个部分

| 部分 | 核心问题 | 读者产出 |
|---|---|---|
| 为什么评测 | 分数制度从何而来，为什么会失真 | 评测用途声明 |
| 测量原理 | 怎样知道自己真的测到了目标能力 | 能力定义图、任务范围、评分器设计 |
| 系统评测 | 如何分离模型、Harness 与 Skill | 全交叉实验与结果解释 |
| 企业实践 | 怎样把岗位要求变成上岗考试 | 两套完整业务 benchmark |
| 治理与未来 | 如何持续复证并评测评测本身 | 发布门禁、事故回归与生命周期 |

## 两条案例线

**云舟零售**是一家虚构的全渠道零售企业。它从售后助手开始，逐步接入 OMS、WMS、ERP 和供应商协同，最终评估一个能处理履约异常的数字员工。

**星桥硬件**是一家虚构的消费电子公司。它研发一款带传感器与移动应用的智能终端，评测对象要在需求、BOM、测试、缺陷和工程变更之间完成证据闭环。

两条案例不会共享答案。它们共享的是同一套方法：先说清要测什么，再定规则、评分、实验、发布门禁和重新验证的条件。
