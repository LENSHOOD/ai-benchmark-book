# 第四轮评审裁决与修订验收

## 结论

第四轮评审准确复验了 v0.3.0-beta，并确认第三轮 13 项裁决全部与实况一致。它只发现两处非阻断的失效 fragment；本轮核对 VitePress 1.6.4 构建产物后确认 N4-1 成立，已同时修复链接和门禁盲区。N4-2 是评审环境对父仓库与用户约束不可见的披露，不要求书稿或代码行动。

当前补丁版本为 v0.3.1-beta。内部课程与 public beta 继续保持无保留 Go；“学术级权威 v1.0”仍受 87 条未核验来源、关键历史/理论主张的 claim-level 映射和三个横切专题深度阻断。

## 逐项裁决

| 条目 | 裁决 | 实施与验收 |
|---|---|---|
| N4-1 第 9 章错误 Skill 小节锚点 | 采纳并关闭 | 链接从不存在的 `#现有证据告诉了我们什么` 改为实际生成的 `#三组实证结果带来的正确问题`；构建 HTML 的 `href` 与目标 `id` 一致 |
| N4-1 首页成熟度锚点不存在 | 采纳并关闭 | 将成熟度声明升级为 `## 当前成熟度` 正式小节，保留 warning 容器；阅读指南 `/#当前成熟度` 现在可解析 |
| N4-1 fragment 门禁盲区 | 采纳并关闭 | `check_book.py` 不再只剥离 fragment 检查页面；它按 VitePress NFKD、控制字符、标点折叠、数字前缀和重复标题规则生成 slug，并验证所有内部 Markdown fragment |
| N4-2 两项依据在评审边界外 | 记录，无代码行动 | 父 Git 根已由作者环境独立确认；95 文件版本清单继续提供不依赖该事实的补偿性完整性控制。10 万字边界来自用户此前确认，不需要写入评审环境 |

## 防回归验证

- `python3 scripts/check_book.py`：全站内部路由及 fragment 零错误。
- 构建产物检查：第 9 章 `href`、第 10 章目标 `id`、阅读指南 `href` 和首页目标 `id` 四项一致。
- 隔离负向注入：在临时副本把链接改为 `#不存在的验收锚点` 后，`check_book.py` 以非零状态退出并报告 `broken internal anchor`。
- `npm test`：内容、140 条来源、v0.3.1 的 95 文件基线、16 个语义测试、VitePress production build 和 35 页渲染检查全部通过。

## 版本处理

两处修复不改变构念、案例协议或外部证据，只修复发布导航与质量门禁，因此采用补丁版本 v0.3.1-beta。`release/v0.3.0-source.sha256` 作为历史基线保留；当前源文件由新的 `release/v0.3.1-source.sha256` 标识，二者不覆盖。

## 剩余边界

第四轮没有提供应立即扩展 v1.0 范围的新证据。后续仍应按风险和引用频次核验 87 条非 arXiv 来源，补强历史/理论论断的局部引文，并在公平、数据劳动和在线人因确有足够证据与篇幅时形成横切内容。英文索引、每章元信息、axe/pa11y、Radar owner 与混合效应完整代码仍是增强项，不应与当前 beta 的正确性修复混为一谈。
